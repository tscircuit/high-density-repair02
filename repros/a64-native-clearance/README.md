# A64 native clearance repair cost

Run `bun repros/a64-native-clearance/repro.ts` to repair the captured native
69-route node, regenerate `board.svg`, and print elapsed time and the output hash.
The region has 166 fixed neighboring routes. The SVG is generated by Repair02's
existing visualizer; it is a repair-stage view, not a completed board.

The native pads, placements and rules come from the real OLIMEX A64-OLinuXino
rev H DDR subsystem, [OLIMEX/OLINUXINO revision 85eee9c](https://github.com/OLIMEX/OLINUXINO/tree/85eee9c17ee13af65617d73bdd94de7ec49cfb42/HARDWARE/A64-OLinuXino).
Attribution: OLIMEX Ltd.; [CC-BY-SA-3.0-US](https://creativecommons.org/licenses/by-sa/3.0/us/).

The TSX importer and native board asset are from
[core-ddr-benchmark 5a2cfa2](https://github.com/ShiboSoftwareDev/core-ddr-benchmark/tree/5a2cfa2382097432214ef567a3e1e97144b33f71/circuits).
The routing experiment used published tscircuit 0.0.3188 / Core 0.0.2380 with
an unpublished autorouter build from 6cdb364 plus Tiny 46f9766 (#321).
That planning experiment was rejected for routing regressions. This fixture
preserves its actual `cmn_14` Repair02 input without changing geometry or rules;
it demonstrates computation cost and does not establish a DRC-clean A64 route.
Physical through-via spans are included. The optimization must preserve the
complete repair result and all unresolved findings.
